# 01. 現状診断と論点整理

## 1. 診断の狙い

「承認形跡がない／運用されているか不明／再発する」という課題を、**監査でテストできる具体的な統制ポイント**に翻訳する。
抽象的な問題意識のままでは監査手続に落ちないため、まず台帳の実データで事実を確認した。

## 2. 実データによる確認（直近四半期の業務起因インシデント）

インシデント管理シートの `詳細24-3-業務起因_作業起因-2025-Q3`（業務起因インシデント **15件**）を試査した結果。

| 確認項目 | 結果 | 示すこと |
| --- | --- | --- |
| インシデントレベル | **15件すべてレベル3** | 規程上、全件が「グループ長→社長」承認を必要とする重要案件 |
| 恒久対応の担当者（PL）未設定 | **3件 / 15（20%）** | そもそも恒久対応の実行責任者が決まっていない |
| 恒久対応 承認日 が空欄 | **5件 / 15（33%）** | レベル3にもかかわらず**承認の形跡（日付）がない** |
| 対応完了日 が空欄 | **8件 / 15（53%）** | 恒久対応が完了したのか判別できない（対応中を含む） |
| 対応完了確認日（事務局） が空欄 | **15件 / 15（100%）** | 事務局による**完了確認の統制がまったく回っていない** |
| 恒久対応の有効性 評価 | 実質未評価 | 「効いたか」を誰も判定していない |

> 補足: 承認者名だけ入り承認日が空欄のケース（例: No.909, 918, 930, 951）があり、「名前はあるが、いつ・本当に承認されたか」が追えない。
> また No.896 は恒久対応承認日（7/15）が暫定対応承認日（7/16）より前という日付矛盾があり、記録の信頼性自体に検証余地がある。
> レベル3の承認者がグループ長級の氏名にとどまり、規程が求める**社長承認まで到達している形跡が確認できない**点も論点。

### 再発の構造（質の問題）

同一四半期に、CRM/BDの配信・制作ミスが連続発生している（例: No.942「本日最終日」誤配信、No.943 バナー見切れ、No.944 曜日誤り、No.946 クーポン未配布）。
これらの恒久対応策は「ダブルチェックを徹底」「正しさチェックを入れる」「周知する」といった**人の注意力に依存した対策**に偏っている。
人依存の対策は再発を構造的に止められないため、**同種インシデントの再発**という課題の直接原因になっている。

## 3. 4つの統制ギャップ（監査対象の定義）

上記から、課題を次の4つの統制ポイントに整理する。監査はこの4点を証憑で確かめる。

| # | 統制ポイント | あるべき状態 | 観察された欠落 |
| --- | --- | --- | --- |
| G1 | **承認**（Authorization） | 恒久対応策がレベルに応じた正しい権限者の承認を受け、承認者名＋承認日が記録されている | 承認日欠落33%、社長承認到達が不明 |
| G2 | **実装・運用**（Implementation） | 対応策が文書上の記載で終わらず、実際の業務（手順書・チェックリスト・システム設定・権限・アラート）に反映されている | 台帳上は判定不能。現物確認が行われていない |
| G3 | **有効性・再発**（Effectiveness） | 対応後に同種インシデントが再発していない／構造的に再発を防ぐ設計になっている | 有効性未評価、人依存策による再発 |
| G4 | **完了確認**（Closure） | 事務局が完了を確認し、台帳がクローズされている | 完了確認日100%空欄 |

## 4. 監査論点（Audit Questions）

- Q1. 業務起因インシデントの恒久対応策は、レベルに応じた**正しい承認者**の承認を、**形跡（日付）付き**で受けているか。（G1）
- Q2. 承認された恒久対応策は、**実際に運用に反映**されているか。現物で確認できるか。（G2）
- Q3. 恒久対応策は**有効**か（同種再発がないか）。対策が人依存でなく**再発を構造的に防ぐ設計**か。（G3）
- Q4. 事務局の**完了確認**まで到達し、台帳がクローズされているか。（G4）

## 5. 診断上の留意点（納得感のために）

- 空欄のすべてが「不備」ではない。**完了予定日が未到来で対応中**の案件（例: No.899 予定8/31、No.951 予定10/31）は正常。
  監査では「期限内で対応中」「期限超過・放置」「完了だが承認・確認形跡なし」を**区別**して評価する。
- 目的は担当者個人の断罪ではなく、**プロセスが途切れる箇所**を特定して仕組みで塞ぐこと。この姿勢を監査の入口で明示する。
