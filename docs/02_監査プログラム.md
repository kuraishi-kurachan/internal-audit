# 02. 監査プログラム — 業務起因インシデント 恒久対応策の運用監査

第13期 特別項目「インシデントの恒久対応策の運用状況の確認」の具体的手続。

## 1. 監査目的

業務起因インシデントについて、恒久対応策が **①正しく承認され（G1）、②実際に運用され（G2）、③有効に機能し再発を防ぎ（G3）、④完了確認までクローズされている（G4）** ことを、証憑により確かめる。

## 2. 監査アプローチ

**ヒアリング（認識・自己評価の確認）＋ 証憑試査（少数サンプルの裏取り）** の二層構成。
ヒアリングのみで完結させず、必ず現物で裏を取る。これが「運用確認」の本質。

## 3. 母集団（Population）

- 対象: 監査対象部門（グループ単位）の、**前回監査以降〜監査基準日**に発生した**業務起因**インシデント（`原因分類` が「業務起因」で始まるもの）。
- 出典: 全社インシデント管理シート `【閲覧専用】全社シートマージ` を `担当部門`・`原因分類`・`発生日` で抽出。
- 監査人が事前に母集団リストを作成し、件数・レベル分布を把握してからヒアリングに臨む。

## 4. サンプリング（現場負担とのバランス）

| レベル | 抽出方針 |
| --- | --- |
| レベル3 | **原則全件**（重要案件・母集団が小さいため悉皆が現実的） |
| レベル2 | 各部門から**リスクベースで抽出**（金額影響大／顧客影響大／再発性あり／承認・完了欄が空欄 を優先） |
| レベル1 | 対象外（承認不要のため。ただし件数の異常増は別途モニタリング） |

- **1部門あたりのサンプル上限を設定**（目安5〜8件）。負担が過度にならない範囲に収める。
- 抽出基準を監査調書に明記し、被監査部門にも開示する（恣意性を排し**納得感**を担保）。

## 5. テスト手続（サンプル1件ごと）

各サンプルについて、以下の「3＋1点」を証憑で確認する。**現物を1点見せてもらう**方式とし、新規資料の作成は求めない。

### G1. 承認（Authorization）
- 台帳の `恒久対応承認者`・`恒久対応承認日` が記入されているか。
- **承認者がレベルに応じた正しい権限者**か（Lv2=グループ長／Lv3=グループ長→社長）。Lv3は社長承認の形跡（役員会確認欄・Slack承認・稟議等）まで確認。
- 承認日が対応策の確定日として整合しているか（暫定→恒久の順序矛盾がないか）。
- **証憑例**: 承認記録（シート承認列／Slack／稟議システム）、役員会・みんな会議の共有記録。

### G2. 実装・運用（Implementation）
- 恒久対応策が**実際の業務に反映**されているか。「記載どおりに運用されている」ことを現物で確認。
- **証憑例**（対策の性質に応じ1点）:
  - 手順書・マニュアル・チェックリストの**改訂版**（更新日が対応日以降）
  - システム修正: リリース記録／設定画面／権限設定／アラート設定のスクリーンショット
  - 運用ログ: チェックリストの記入実績、アラート発報履歴 等
- 「対応済」と台帳にあるが現物が出てこない場合＝**運用されていない疑い**として指摘。

### G3. 有効性・再発（Effectiveness）
- 恒久対応の完了日**以降**に、同種インシデントが再発していないかを台帳で確認。
- 対策の**設計品質**を評価: 「ダブルチェック徹底」「周知」など**人依存**の対策に留まっていないか。
  再発リスクが高い業務は、システム制御・自動化・権限分離など**構造的対策**への引き上げを推奨事項とする。
- **証憑例**: 台帳の時系列（同一 `原因分類`・類似タイトルの再発有無）。

### G4. 完了確認（Closure）
- 事務局の `対応完了確認日` が記入され、台帳がクローズされているか。
- 完了予定日を超過して未完了のまま放置されていないか（期限管理の有効性）。

## 6. 評価基準（4段階）

| 評価 | 定義 |
| --- | --- |
| ○ 有効 | 4点すべてに問題なし。承認・運用・有効性・完了確認が証憑で確認できる |
| △ 一部不備 | 実体は運用されているが記録・形跡に不備（例: 承認日未記入、完了確認未実施） |
| × 不備 | 承認を受けていない／運用の証憑が出てこない／同種が再発している |
| － 対象外／対応中 | 完了予定日が未到来で正常に対応中。次回フォロー対象 |

## 7. 部門長ヒアリングとの統合

- 内部監査シートの固定設問に、**インシデント恒久対応の運用**セクション（[templates/01_ヒアリング追加設問.md](../templates/01_ヒアリング追加設問.md)）を1ブロック追加。
- ヒアリングで部門長の**認識と自己評価**を聞き、上記サンプル試査で**裏取り**する。
- 認識と実態の乖離（例: 「運用している」と回答→現物が出てこない）自体が重要な発見事項。

## 8. スケジュール整合（第13期計画）

計画の月次サイクルに本手続を織り込む。

| 記号 | 工程 | 本特別項目での作業 |
| --- | --- | --- |
| ● | 監査実施通知 | 母集団リスト・サンプル・確認してほしい証憑の観点を事前送付（現場が準備しやすいように） |
| ★ | 監査実施・報告書提出 | ヒアリング＋証憑試査（G1〜G4）。調書化し監査報告書へ |
| ◆ | 改善指示書発信 | ×・△の発見事項について改善を指示 |
| △ | 改善実施計画書受取 | 部門から是正計画（対策・期限・責任者）を受領 |
| ○ | 改善状況確認書受取 | 是正完了を確認しクローズ。特にG3は再発有無を一定期間後に再確認 |

## 9. 監査人の独立性

計画どおり、内部監査担当が所属する部門（経営管理室等）の監査は**別の担当者**が実施する。恒久対応策の承認に監査担当が関与している案件は、レビュアーを分ける。
