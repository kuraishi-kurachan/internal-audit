# 03. 仕組み提案 — 監査を支える3レイヤー

監査を「毎回の力技」にしないための支援の仕組み。**発生源で品質を担保 → 監査を自動化 → 再発を検知**の3レイヤーで構成する。
いずれも既存のインシデント管理シートに対する追加設定で実現でき、新規システム投資は不要。

---

## レイヤー1: 発生源統制（台帳の入力統制強化）

課題の多く（承認日空欄・PL未設定・完了確認空欄）は、**台帳を埋める時点**で防げる。監査で毎回指摘するより、入力段階でガードする方が低コスト。

### 1-1. レベルに応じた必須項目化
- レベル2・3では `恒久対応担当者(PL)`／`恒久対応承認者`／`恒久対応承認日` を**必須**に。
- 未入力のまま「対応完了」にできないよう、完了フラグ側にチェック（下記ステータス自動判定）。

### 1-2. 承認者はプルダウン化
- `恒久対応承認者` をデータの入力規則（プルダウン）にし、**権限者マスタ**から選択させる。
- レベル3は社長を含む承認到達を担保するため、`社長承認日` 列（または役員会確認）を必須化。

### 1-3. 「有効性」を選択式にする
- `恒久対応の有効性` 列を自由記述でなく選択式に: `有効 / 一部有効 / 未評価 / 再発あり`。
- これにより有効性が**必ず一度は判定される**運用にする（現状は実質未評価）。

### 1-4. 条件付き書式で「抜け」を可視化
- 承認日が空欄 → セルを赤。
- 完了予定日を超過かつ対応完了日が空欄 → 行を黄（期限超過アラート）。
- 対応完了確認日（事務局）が空欄で対応完了日あり → 事務局タスクとしてハイライト。

### 1-5. ステータス自動判定（数式）
`ステータス` 列を手入力でなく数式で自動判定する例（列は `全社シートマージ` 基準: 承認日=X, 対応完了日=Z, 完了確認日=AA）。

```
=IF(AND($X2<>"", $Z2<>"", $AA2<>""), "クローズ",
 IF($X2="", "承認待ち",
 IF(AND($Y2<>"", TODAY()>$Y2, $Z2=""), "期限超過",
 IF($AA2="", "事務局確認待ち", "対応中"))))
```

## レイヤー2: 監査ビュー（自動抽出ダッシュボード）

監査人が母集団抽出と欠落チェックを手作業でやらないための、**監査専用シート**。全社マージを参照するだけの読み取り専用ビュー。

### 2-1. 要対応インシデントの自動抽出
「業務起因 かつ（承認日空欄 or 完了確認空欄 or 有効性未評価）」を自動抽出（列は `全社シートマージ` 基準: 原因分類=N, 有効性=U, 承認日=X, 完了確認=AA）。

```
=QUERY('【閲覧専用】全社シートマージ'!A2:AH,
  "select A, C, O, I, X, AA, U
   where N contains '業務起因'
     and (X is null or AA is null or U is null or U = '未評価')
   order by C, O desc", 0)
```

### 2-2. 部門別KPIダッシュボード
部門×以下の指標をピボット/集計で可視化し、監査の重点部門を判断:

| KPI | 意味 |
| --- | --- |
| 業務起因インシデント件数 | 発生量 |
| 承認形跡欠落率（承認日空欄 / 件数） | G1の運用度 |
| 期限超過率（超過未完了 / 件数） | G4の期限管理 |
| 事務局未確認率（完了確認空欄 / 件数） | G4のクローズ統制 |
| 再発件数（同種の再発） | G3の有効性 |

- これにより、監査対象部門の**重点度**を数値で説明でき、経営報告もこの指標で行える。

### 2-3. 監査前チェックリストの自動生成
- 抽出結果をそのまま「この部門で確認する母集団・サンプル・観点」として監査通知（●）に添付。現場は該当分だけ準備すればよい＝**負担軽減**。

---

## レイヤー3: 再発検知

「同種インシデントの再発」を人手のレビューに頼らず検知する。

### 3-1. タグ運用
- `原因分類` に加え、業務観点の**タグ**列を追加（例: `配信ミス` `誤送金` `同梱期日` `権限設定`）。
- プルダウンで統一し、表記ゆれを防ぐ。

### 3-2. 再発フラグ
- 恒久対応完了日**以降**に、同一部門×同一タグのインシデントが発生した場合に自動でフラグ。
- 再発が出た恒久対応策は「有効性 = 再発あり」に更新し、監査の重点サンプルに自動昇格。

### 3-3. 対策品質のセルフチェック
- 恒久対応策の入力時に「この対策は人の注意に依存していないか？ 構造的に防げるか？」の観点をガイド表示（ガイドシートに追記）。
- 人依存の対策が続く業務は、システム化・自動化の起案につなげる（再発の根本対策）。

---

## 導入ステップ（無理なく定着させる）

1. **今期監査で現状を可視化**（レイヤー2の監査ビューを先に作り、母集団と欠落を数値化）。
2. 監査の指摘を根拠に、**レイヤー1の入力統制**を事務局と合意して導入（承認日必須・有効性選択式・条件付き書式）。
3. 定着後に**レイヤー3の再発検知**を追加。
4. 次期以降は、監査ビューのKPIで**モニタリング型**に移行し、監査工数を圧縮する。

> 実データ（`【閲覧専用】全社シートマージ` は閲覧専用）への設定投入は編集権限が必要。
> 監査用ビューは別ファイルに `IMPORTRANGE` で複製して構築すれば、原本を触らず監査人側で運用できる。
