# 内部監査シート 追加設問ブロック — インシデント恒久対応の運用

既存の固定設問（No.1〜16）の末尾に、新カテゴリ「**インシデント管理**」として追加する。
評価は既存と同じ列構成（`項目` / `チェック項目` / `評価` / `具体的状況等`）に合わせる。

ヒアリングでは部門長の**認識・自己評価**を確認し、別途サンプル試査（監査調書）で**裏取り**する。

| No | 項目 | チェック項目 |
| --- | --- | --- |
| 17 | インシデント管理 | 自部門で発生した業務起因インシデントを把握しており、インシデント管理シートに漏れなく起票・記録している。 |
| 18 | インシデント管理 | 恒久対応策について、レベルに応じた承認者（Lv2:グループ長／Lv3:グループ長→社長）の承認を受け、承認者名・承認日が記録されている。 |
| 19 | インシデント管理 | 承認された恒久対応策が、実際の業務（手順書・チェックリスト・システム設定・権限・アラート等）に反映され運用されている。※現物を提示できる |
| 20 | インシデント管理 | 恒久対応策の有効性を確認しており、対応後に同種インシデントが再発していない。 |
| 21 | インシデント管理 | 恒久対応策が「注意・ダブルチェック・周知」など人依存の対策に偏らず、再発を構造的に防ぐ設計になっているか検討している。 |
| 22 | インシデント管理 | 事務局の完了確認まで到達し、期限超過・未完了のまま放置されている案件がない。 |

## ヒアリングの進め方（監査人メモ）

- 各設問はまず「はい/いいえ」ではなく**具体例で語ってもらう**（例: 「直近の恒久対応を1つ挙げ、承認と運用状況を教えてください」）。
- No.19・20は口頭回答で終わらせず、**現物を1点**その場で提示してもらう（新規作成は不要、既存物でよい）。
- 冒頭で監査の目的を明示: 「担当者の評価ではなく、プロセスが途切れる箇所を一緒に見つけて仕組みで塞ぐこと」。

## 評価の記入例

- ○: 承認・運用・有効性・完了確認が現物で確認できた。
- △: 運用実体はあるが記録に不備（例: 承認日未記入）。→改善指示（記録運用の是正）。
- ×: 承認なし／現物が出てこない／同種が再発。→改善指示（対策の再設計を含む）。
